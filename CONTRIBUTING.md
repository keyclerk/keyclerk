# Contributing

Issues are welcome: a question, a bug with the steps to reproduce it, a place where a decision record or the
documentation is unclear, or a deployment need the engine does not meet. A security problem goes to the private
reporting form instead (SECURITY.md), never to a public issue.

Pull requests from outside contributors are not accepted yet. KeyClerk will ask them to accept a contributor licence
agreement (`CLA.md`, a draft under review, not in force); until it is published, please open an issue, and a change
you propose there may be made by the maintainers.

AI-assisted work says so: a commit in an `Assisted-by:` trailer, a pull request by ticking its level of AI use in
the template (`.github/pull_request_template.md`).

## What every change carries
- **A test for what it changes.** New behaviour, a new refusal or a fixed bug comes with a test that fails without
  it. The whole suite stays green: `python -m pytest`, and the policies' own tests, `opa test keyclerk/policy/`, with
  `python tools/build_policy.py --check` showing the compiled policies match their sources.
- **Intent in a decision record.** A change of what the engine does or promises starts as a decision record in
  `docs/decisions/`, in the shape of the records there; a change that builds what a record says links to it. A record
  is amended, never rewritten.
- **No deployment in the engine.** The engine names no deployment and holds no deployment's rules; a test fails if a
  file does. Rules belong in a deployment's configuration (`keyclerk/schema/config.schema.json`).
- **The edge protocol moves with its vectors.** A change an edge would notice changes the protocol's specification and
  its conformance set (`tests/conformance/edge.json`, generated by `tools/gen_edge_conformance.py`, never written by
  hand), published at github.com/keyclerk/edge-protocol.
- **Clean files.** `reuse lint` (every file licensed), `python tools/leak_gate.py .`, `ruff check`, and a line in
  `CHANGELOG.md` for anything a deployer or an edge implementer would notice.
- CI runs all of these on every pull request and fuzzes the bundle verifier. A pull request merges only with every
  check green and the branch up to date.
